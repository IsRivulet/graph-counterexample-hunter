# Skill / baseline 预跑结果（2026-11-06）

## 设置

- 案例：E2E-01（应找到反例）、E2E-02（穷举范围内无反例）
- 两组都使用 `gpt-6-luna`、相同后端版本、相同输入和 300 秒单题超时
- Skill 组加载 `SKILL.md`；baseline 组不加载 `SKILL.md`
- 两组都是新会话；每题的 token 和墙钟时间取自各自运行日志

## 初步观察

- 两组在 1 个反例存在案例上都找到经 oracle 验证的反例；在 1 个无反例案例上都正确完成穷举。这个样本太小，不能据此声称 Skill 提高了发现率。
- 两组 E2E-01 都返回同一张 K₂,₂ 图，并都如实说明只证明了范围内顶点数最小、没有证明边数最小。两组都没有记录缩小调用，因此该案例的自动评分未全通过；这也是下一轮值得追踪的质量项。
- 两题合计：Skill 组输入 247,189 token、输出 2,787 token、209.97 秒；baseline 输入 270,060 token、输出 2,900 token、202.47 秒。Skill 组输入 token 少约 8.5%，输出 token 少约 3.9%，总用时多约 3.7%。只有两题且单题波动较大，这些差异仅作预跑记录。
- 两题均要求人工复核，当前 `scores.json` 的严格通过状态仍待人工评审；本次评分没有进行盲评，因此不填主观质量分。

## 缩小流程改进后的复跑

将 Skill 中“若有缩小入口，优先”改为找到有效反例后必须依次执行 **原图核验 → reducer → 对 reducer 返回图单独复核**。即使 reducer 没有改进图，也记录结果并复核。报告协议也明确了这项要求。更新后只重跑 Skill 组同样的 E2E-01、E2E-02；基线组沿用上表记录。

| 案例 | 更新后 Skill 结果 | 自动评分 | 输入 token | 输出 token | 用时 | 后端调用 |
|---|---|---:|---:|---:|---:|---:|
| E2E-01 | 找到相同的有效 K₂,₂；reducer 返回 `no_improvement`，缩小图经独立 verifier 复核通过 | 通过 | 196,617 | 3,429 | 175.5 秒 | 4 |
| E2E-02 | 穷举完成，范围内未发现反例 | 通过 | 102,128 | 1,012 | 74.9 秒 | 1 |

更新后自动评分为 **2/2**，而旧 Skill 和基线各为 **1/2**。E2E-01 的有效反例召回没有变化，改进在于缩小和复核链路现在完整记录；本次也确认图没有可接受的单顶点/单边删除改进。两题的严格评分仍待人工复核，因此不能写成最终严格通过。
